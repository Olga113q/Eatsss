# Передача проекта «Что приготовить?» (для новой сессии Claude Code на ПК)

Репозиторий: Olga113q/Eatsss, рабочая ветка **ccr-75b67d4e-vc2cwf** (всё здесь, в main не сливалось).
Сайт: https://olga113q.github.io/Eatsss/recipes-app/ (GitHub Pages с этой ветки, обновляется ~1–2 мин после пуша).
APK: https://github.com/Olga113q/Eatsss/releases/download/android/chto-prigotovit.apk

## Что это
Личный сайт (и Android-приложение) по типу Supercook: отмечаешь продукты дома → рецепты, которые можно
приготовить; плюс недельный план ужинов с корзиной из реальных цен магазинов СПб (Оптиков 47 к1).
Всё статика, без сервера: `recipes-app/index.html` + `app.js` + `planner.js` + `style.css`, данные в `data/*.js`.
Состояние пользователя — в localStorage (ключи `wtc:*`), на каждом устройстве своё.

## Структура
- `recipes-app/data/recipes.js` — ~6950 рецептов eda.ru БЕЗ шагов (5 МБ, gzip ~0,95 МБ) + `data/steps.js` — шаги
  (`window.RECIPE_STEPS[id]`, 9 МБ), догружается в фоне (app.js `loadSteps`), окно рецепта дорисовывает шаги само.
  Раньше всё было одним файлом 14 МБ: в приложении грузилось ~70 с, на телефоне через VPN обрывалось («Не найден файл
  data/recipes.js»). Если recipes.js не загрузился — app.js один раз качает его заново и перезапускает app.js+planner.js,
  иначе показывает экран «Не удалось загрузить рецепты» с диагностикой и «Повторить».
  Старое описание: Собирается `tools/build_data.py` из SQL-дампа
  https://github.com/Maximilyanus29/recipes (`docker/docker-entrypoint-initdb.d/recipes.sql`, таблица recipe_temp).
- `tools/normalize.py` — правила «название ингредиента → продукт» (~570 продуктов; курица разделена на
  филе / ножки / крылья / целая). Правила — по порядку, первое совпавшее. ВАЖНО: в JS-регэкспах `\b` не работает
  с кириллицей — используй `(?![а-яё])`.
- `data/images.js` — фото блюд (img02.rl0.ru, вариант 1280x720 из JSON-LD страницы eda.ru), собирал workflow
  `.github/workflows/recipe-images.yml` (`tools/fetch_images.py`), уже собрано для 6951 рецепта.
- `data/prices/magnit.json`, `data/prices/ozon_fresh.json` — цены, собранные сессией на ПК со страниц магазинов
  (скрипты в `prices/scripts`, отчёт `prices/README.md`, чего не хватает — `prices/missing.md`).
- `tools/build_prices.py` → `data/plan.js`: сопоставление товаров магазинов продуктам (строго: продукт по первым
  словам названия, REQUIRE/NEG-правила, отсев готовой еды/маринадов), примерные цены (APPROX, помечены «≈»),
  пересчёт количеств из рецептов в граммы. У Ozon Fresh товары «X–Y кг» — цена за кг (умножается на средний вес).
  После правок normalize.py нужно пересобрать ОБА: build_data.py и build_prices.py.
- `planner.js` — план на неделю: N человек, дни, завтрак/обед/ужин (по умолчанию ужин), бюджет, магазин;
  «готовить с запасом на обед» (порций = 2 × людей, по умолчанию вкл.); «курицу — целой тушкой» (разделка ~22% филе,
  32% ножки, 10% крылья); каждое блюдо = белок + гарнир (иначе добавляет гарнир/белок); штраф за остатки
  скоропортящегося и проходы «доесть купленное»; разделы Меню / Корзина / Остатки после недели.
- Окно рецепта: переключатель порций с пересчётом количеств; из плана открывается на запланированные порции.
- Фильтры с галочками: приём пищи, особое питание, тип блюда, подраздел eda.ru, кухня; «только блюда» (скрывает
  напитки, соусы, тесто, рецепты < 4 продуктов).
- PWA: `manifest.webmanifest`, `sw.js` (офлайн, network-first), иконки `recipes-app/icons/`.
- `android-app/` — Capacitor 7 оболочка: локальная страница сразу делает `location.replace` на сайт
  (`server.allowNavigation: olga113q.github.io`), `android.adjustMarginsForEdgeToEdge: auto`.
  APK собирает `.github/workflows/android.yml` (при изменениях в android-app/ или вручную), кладёт в релиз
  `android`; versionCode = номер сборки, подпись постоянным ключом `android-app/keystore/debug.keystore`
  → новые APK ставятся поверх без потери данных. Обновления сайта приходят в приложение сами.

## Что работает (проверено в браузере)
Подбор рецептов, фильтры, избранное, список покупок, план на неделю с корзиной и остатками, пересчёт порций,
офлайн-режим сайта, кнопка «назад» закрывает окна (через history.pushState).

и нижнюю панель, «назад» сначала закрывает окна, без интернета (режим полёта) после первого запуска работает.
Исправлено: белые значки строки состояния (плагин `@capacitor/status-bar`, style LIGHT), кнопка
«Показать ещё (-40)» при 0 рецептов, подсказка «Загружаю рецепты…» на время первой загрузки (на эмуляторе ~40 с).
**Подпись APK:** сборки 1–3 подписывались случайными ключами (копия в ~/.android не подхватывалась) → новый APK
не ставился поверх («signatures do not match»). С сборки 4 подпись явная (`android.injected.signing.*`) ключом
`android-app/keystore/debug.keystore`, workflow сверяет SHA256 сертификата. На телефоне со старой сборкой нужно
ОДИН раз удалить приложение и поставить новую (выбранные продукты/план в нём сбросятся), дальше — поверх.

**Обновления APK (со сборки 5):** CI вписывает номер сборки в User-Agent («ChtoPrigotovitApp/N»,
`appendUserAgent` в capacitor.config.json); `recipes-app/app-update.js` сравнивает его с «сборка N» в названии
релиза `android` (GitHub API) и показывает плашку «Скачать / Позже»; ссылка открывается в браузере телефона.
Работает, только пока репозиторий публичный (Pages и релиз без авторизации). Отладка: `__checkAppUpdate(1)`.

Эмулятор на ПК: SDK в `D:\Android\Sdk` (adb, emulator, образ android-35 google_apis x86_64), JDK 17 в
`D:\Android\jdk17`, AVD `pixel35` в `D:\Android\avd`. Запуск:
`set ANDROID_AVD_HOME=D:\Android\avd` и `D:\Android\Sdk\emulator\emulator.exe -avd pixel35`.
Отладка WebView: `adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>` → Chrome DevTools Protocol.

## Правила плана (по просьбе пользователя, 06.11)
- Повтор вида блюда за неделю (`familyOf`: плов, борщ, котлеты, паста, лазанья…) — только штраф +150, не запрет:
  пользователь меняет лишнее кнопкой «заменить».
- «Заменить» (`replaceCandidates`): если в корзине целая тушка, а блюдо было на её часть (филе/ножки/крылья/курица),
  новое блюдо — на ту же часть, чтобы тушка тратилась. Последние 15 показанных на месте блюд не повторяются (`slot.skip`).
- Остатки — единое правило `leftOf`: мясо/птицу/рыбу готовят всей упаковкой (лишнее ≤40% — не остаток, в корзине
  «готовим всю упаковку»); тушку готовят целиком (ножки/крылья/бёдра вместе, каркас на бульон) — части не остаток,
  пока их ≤40% тушки; прочее скоропортящееся <25% упаковки не показываем; крупы/специи/масло — «хранится».
- Адреса магазинов в приложение не выводятся (убраны из plan.js, data/prices/*.json, парсеров).
- Известная ошибка данных: «Окорочка утиные» → «Куриные ножки» (normalize.py). (Сердечки и желудки — один
  продукт «Куриные сердечки» намеренно.)
